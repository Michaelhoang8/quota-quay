Create a policy

Policies are immutable. Create a new name to change capacity or refill rate. Requests are isolated by policy and client.

API & operational boundaries

POST /api/policies creates a policy. POST /api/policies/{name}/consume accepts request_id, client, and cost. Successful admission returns HTTP 200; denial returns 429 and Retry-After. Conflicting reuse of an ID returns 409.

All decisions use a SQLite write transaction. Exact integer microtokens avoid floating-point drift. Backward clock movement is clamped per client; a large forward jump can refill to capacity. Retry delays are measured at the original decision time and are not reservations.

This is a local service and reference implementation, not a distributed gateway. It has no authentication, tenant authorization, retention cleanup, or external traffic interception. Bounds: 100 policies, 2,000 clients and 10,000 receipts per policy. Stop the server before backing up the entire data directory.
